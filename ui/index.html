Platform Overview
📡
Multi-Source Aggregation
Scrapers pull from the Berlin Police API and beyond into a unified database. The BaseScraper interface makes adding a new source a single Python class. Registration in run_all.py enables the scraper.
📰
Curated Editorial Pipeline
Approved contributors submit articles via Telegram bot. AI content-reviewer agent auto-tags and summarizes. You (the editor) approve or reject via admin API. No open forms, no spam.
🔍
Bilingual Full-Text Search
PostgreSQL FTS with custom german_unaccent and english_unaccent configurations. search_translations table maps English terms to German — "climate housing" finds "Klima Wohnen" events. Results ranked by ts_rank.
🤖

LLM agent for auto-tagging content and generating summaries. Configurable via AI_PROVIDER env var. Supports Ollama (default: gemma3:12b) or OpenAI-compatible APIs. Admin-only endpoints.
🗄️
dbt Medallion Pipeline
Bronze → Silver → Gold medallion architecture. 8+ dbt models stage, intermediate, and materialize data into API-ready marts with GIN-indexed search_vector columns for fast full-text queries.
🛡️
Security-First Design
No public write endpoints. All POST/PUT/DELETE require Authorization: Bearer <ADMIN_API_KEY>. Telegram bot uses ALLOWED_USER_IDS whitelist. Full review_log audit trail for every agent action.

Pipeline

Agentic Content Pipeline

An agentic-driven journal with a human-in-the-loop at every decision point. Approved contributors submit via Telegram, AI agents review, and you make the final call before anything goes live.

The Full Pipeline
Step 1
Contributor Sends Article via Telegram
An approved contributor (whitelisted via ALLOWED_USER_IDS) sends a Markdown message to the Telegram bot. First line = title, rest = body. The bot stores it in the submissions table with status = 'pending'.
Step 2
Content-Reviewer AI Agent Review
You trigger POST /admin/submissions/{id}/agent-review. The content-reviewer agent (via Ollama/OpenAI) reads the submission and returns suggested tags and a one-sentence summary. Status changes to agent_review. The review is logged in review_log.
Step 3
Editor Approves or Rejects
You review the agent's suggestions via the admin API. POST /admin/submissions/{id}/approve creates a raw_posts row with status = 'draft'. POST /admin/submissions/{id}/reject sets status to rejected. You can also call this manually with optional editor notes.
Step 4
Draft Post in raw_posts
On approval, a new row is inserted into raw_posts with status = 'draft'. The slug is auto-generated from the title with collision handling. The submission is linked via submission_id.
Step 5
Editor Publishes
POST /admin/posts/{id}/publish sets status = 'published' and records published_at. The post appears in public /posts and /search endpoints. POST /admin/posts/{id}/unpublish reverts to draft.
Step 6
Live on Site + Searchable
The dbt pipeline materializes published posts into mart_posts_api with GIN-indexed search vectors. Public /posts, /posts/{id}, and unified /search endpoints serve the content. Bilingual FTS matches English and German queries.
Agentic Journal Model
👤
Human-in-the-Loop
Every submission passes through a human editor before going live. AI agents assist (tagging, summarizing) but never auto-publish. The editor is the final gatekeeper.
🔐
Curated Submission Only
No open registration or public forms. Contributors are personally invited and whitelisted via Telegram user IDs. The Telegram bot rejects unauthenticated submissions with "Unauthorized."
📋
Full Audit Trail
Every agent action is recorded in review_log — who reviewed, what action (review/edit/approve/reject/request_revision), and notes. The admin_notes field tracks editorial decisions.

System Design

Data Architecture & Security Model

A medallion pipeline (bronze → silver → gold) with dbt transformations. All writes require API key authentication. No public POST/PUT/DELETE endpoints exist.

Data Flow
Sources
Data ingestion layer. Two data sources: Berlin Police API scraper (scraper/sources/berlin_police.py) pulls assembly data into raw_assemblies. Telegram bot (bot/bot.py) receives curated article submissions into submissions.
Bronze
Raw landing zone. raw_assemblies stores raw event scrapes with original field names (datum, von, bis, thema, plz, strasse_nr, aufzugsstrecke). raw_posts stores blog posts with status tracking. No transformations applied.
Silver
Cleaned & enriched. dbt staging models normalize field names, parse dates, clean postcodes. Intermediate models join with district lookups, apply tag taxonomies, and generate search vectors with german_unaccent.
Gold
API-ready marts. mart_events_api and mart_posts_api materialize final views for FastAPI queries. GIN-indexed search_vector columns enable ts_rank-ranked full-text search across both languages.
Security Model
🔑
API Key Authentication
All admin endpoints use HTTPBearer or X-API-Key header. secrets.compare_digest prevents timing attacks. Key set via ADMIN_API_KEY env var. Stored hashed in admin_api_keys table.
🚫
No Open Write Endpoints
All public endpoints are read-only GET requests. No POST /posts, no POST /submit. The only write path is submissions via Telegram bot (whitelisted users) or admin API (key required).
📋
Telegram Whitelist
ALLOWED_USER_IDS env var defines comma-separated Telegram user IDs. Unauthorized users receive "You are not authorized to use this bot." No public bot commands beyond /start.
📝
Audit Trail
Every moderation action is logged in review_log with agent name, action type (review/edit/approve/reject/request_revision), and notes. Submissions track reviewed_by and reviewed_at.
